# 实验方法（EXPERIMENTS）

本文档说明如何在 omega-cognitive-kernel 中做实验：怎么保证出错可以回退，怎么避免盲目前进，失败后怎么处理，以及怎么标注结论的可信程度。

---

## 十、L2 频谱干预诊断与预注册验收（2026-11-25）

基线：`origin/main` 的 `b47d55c`。功能分支：`feat/l2-spectral-diagnostics`。
先完成信号、提交、执行、结果四层诊断，再决定是否保留控制器改动。
不把 commit、cache hit 或频谱 Active 次数作为疗效证据。

### 实验设计

- 发现集：`stable`、`nonstationary`、`regime_shift`、`cyclic_shift`，每个场景
  30 个配对种子，从 `20261115` 开始，每个种子 `12 episodes × 12 steps`。
- 每个分支使用同一决策器、初始状态、环境种子和 L1 配置；基线仅关闭 L2 干预。
- 独立复验种子从 `20270001` 开始，不参与参数选择。
- 报告每个 seed 的差值、配对 Student-t 95% 区间和按 seed 重采样的
  bootstrap 95% 区间。区间是描述性证据，不替代外部效度验证。
- `mean_warm_recovery_steps` 仅在 cache hit 后对应的 commit 真正执行并完成
  最优臂恢复时记录；它不纳入本轮主验收。

### 主假设与停止条件

假设：有效频谱上下文通过受限专家先验改善突变后的 L0 选臂，而非只增加提交数。

1. 主指标：`regime_shift` 的配对 `delta_mean_reward`，95% 区间下界 `> 0`。
2. 安全保护：`stable` 的配对 `delta_mean_reward`，95% 区间下界 `>= -0.01`。
3. 机制条件：报告调制产生率、候选臂改变率、实际执行率；若实际执行率为零，
   不能声称 reward 改善来自 L2。
4. 若信号与下一期 reward/环境变化的相关性接近零，或反事实选臂从未改变，
   先修复该层，不继续叠加探索算法、reward shaping 或回滚调参。
5. 未满足上述标准时不宣称收益；保留诊断和失败记录，再选择换假设、换判据
   或结束路线。不得在看见结果后替换主指标。

### 诊断契约

频谱输出不是 reward 预测器。对 bias/SNR、模型 residual 和专家策略分别评估：
信号在时间 `t` 记录，与 `t+1` 的 reward、最优臂和 regret 对齐。报告分组
Spearman 相关、零方差/缺失样本及置信区间；Pearson 仅作补充。`predicted_residual`
只对实际 residual 校准，不与 reward 混为一谈。时间序列存在重复观测，按 seed
输出的相关性和 bootstrap 区间是探索性诊断，不是独立同分布样本的因果证据。
频谱输入是 `1 - avg_prediction_error`，不是外部 reward，二者不得混称。

L0 dry-run 克隆 UCB 快照，分别应用/移除同一个 L2Policy，报告候选选择和
实际选择的变化，不写磁盘、不执行 patch、不生成环境 reward。反事实 reward
只能在同一环境快照下重新配对采样；模型自评不能当作真实外部收益。

### 消融与边界

按以下顺序逐组件比较：L2 关闭、ResidentController 单独运行、频谱提交许可、
频谱纯度先验、反向快刹、一次性历史折扣、完整方案。每次只增加一个组件。
现有 regime-shift 的 `0.85` 持续折扣属于基线，不作为新功能重复计数。

本轮不默认引入 Thompson sampling、额外 reward shaping 或更严格的 L1 回滚阈值。
这些仅在上述诊断证明对应瓶颈后，另写实验卡比较。频谱偏置实验属于带上下文
启发式门控的非平稳两臂 bandit，不宣称为标准 contextual bandit 或全局最优算法。

### 最终结果与停止决定（2026-11-25）

以下数据来自最终实现以 release 模式运行的 8 份报告，未据结果调参。
每个场景、每组均为 30 个配对种子，`12 episodes × 12 steps`。
区间依次为配对 Student-t 95% 区间、按 seed 重采样 bootstrap 95% 区间。

| 种子组 | 场景 | reward 差 | Student-t 95% | bootstrap 95% | 影响 L0 的种子数 |
|---|---|---:|---|---|---:|
| 发现集 `20261115` | `stable` | 0 | `[0, 0]` | `[0, 0]` | 0/30 |
| 发现集 | `nonstationary` | 0 | `[0, 0]` | `[0, 0]` | 0/30 |
| 发现集 | `regime_shift` | -0.003935185185185179 | `[-0.007031866098688526, -0.000838504271681832]` | `[-0.007175925925925919, -0.001388888888888884]` | 7/30 |
| 发现集 | `cyclic_shift` | 0 | `[0, 0]` | `[0, 0]` | 0/30 |
| 复验集 `20270001` | `stable` | 0 | `[0, 0]` | `[0, 0]` | 0/30 |
| 复验集 | `nonstationary` | 0 | `[0, 0]` | `[0, 0]` | 0/30 |
| 复验集 | `regime_shift` | 0 | `[0, 0]` | `[0, 0]` | 2/30 |
| 复验集 | `cyclic_shift` | 0 | `[0, 0]` | `[0, 0]` | 0/30 |

`stable` 的安全保护通过，但发现集的主指标下界为负，复验集也没有 reward 改善。
在发现集 `regime_shift` 的 4320 个 dry-run 中，只有 9 次改变候选臂，没有一次
直接改变 dry-run 的实际选臂；4320 个 observation 中有 450 个频谱 Active。
因此 commit 或 Active 次数不构成收益证据，频谱历史折扣实际触发次数为 0。
信号相关性是逐 seed 的探索性诊断，不足以建立因果关系；完整数值保留在原始 JSON。

**结论：结束本轮频谱控制路线（已验证，限上述 fixture 和种子）。** 不宣称控制改善，
不继续调整频谱参数、探索算法、reward shaping 或回滚阈值。保留默认关闭的实验开关、
无副作用 dry-run、逐层执行归因、确定性报告和本失败记录，供未来新假设复用。
该结论不否定其他控制算法，也不证明频谱信号在所有环境下无效。

复现方法与报告校验值见 `docs/L2_BENCHMARK.md` 的 “Spectral research experiment”。
原始逐 step 报告较大，不作为源码提交；文档保留命令、精确摘要和原始报告 SHA-256。

## 一、基本原则

1. **可回退**：任何实验都能回到已知的稳定状态。
2. **先写期望，再动手**：没有假设和判据的实验不开始。
3. **失败有去向**：每次失败都必须选择一个明确的下一步。
4. **撤退是正式动作**：撤回改动也要有记录和理由。
5. **结论分级**：每个结论都标明证据强度，不混用。

---

## 二、回退机制

- **打标签**：实验开始前，在稳定点打 tag。
  ```bash
  git tag exp-YYYY-MM-DD-<简称>-baseline
  ```
- **独立分支**：实验在单独分支或 `git worktree` 中进行，不直接在 `main` 上修改。
- **存档未提交改动**：需要暂停时，把改动存起来，而不是丢弃。
  ```bash
  git stash push -m "<实验名>-存档"
  ```
- **失败分支保留**：失败的实验分支不删除，只在文档中标注结论。

## 四、失败后的三种去向

每次失败，只能选择其中一个，不能只是加参数再跑：

1. **换假设**：说明原来的理由不成立，提出新的理由。
2. **换判据**：说明原来的衡量方式不合适，改用更合理的指标。
3. **结束这条路线**：写入文档，说明为什么放弃，留下什么教训。

---

## 五、撤回改动的记录方式

撤回改动和提交改动一样，需要留下记录，写在 `docs/EXPERIMENTS.md` 对应实验下：

- 尝试了什么
- 为什么撤回
- 留下了什么可复用的东西
- 下次如果再做，要避免什么

## 六、结论的证据等级

每个结论必须标注等级：

| 等级 | 含义 | 示例 |
|---|---|---|
| **已验证** | 有数据、有测试、有复现命令 | 5 个种子、12×12 基准，结果稳定复现 |
| **初步观察** | 只有少数几次结果，还不稳定 | 单个种子下看到的差异 |
| **推测** | 没有直接证据，只是合理猜测 | "可能是干预强制换臂导致的" |

**规则**：不能把"初步观察"写成"已验证"，也不能把"推测"当成结论引用。

## 七、示例：L2 干预实验（2026-11-21）

**实验卡摘要**

- 假设：负奖励触发 L2 干预，能影响下一次 bandit 选臂，从而改善长期表现。
- 场景：非平稳、降级、稳定三种环境。
- 种子：5 个，基准为 12×12。

**结果**

| 场景 | 换臂次数 | 奖励差（相对基线） | 最佳臂率差 |
|---|---|---|---|
| 非平稳 | 平均 1.0 次 | -0.0389 | -0.0806 |
| 降级 | 平均 1.0 次 | -0.0264 | -0.3056 |
| 稳定 | 未触发干预 | 持平 | 持平 |

**结论分级**

- "干预后奖励和最佳臂率下降"：**已验证**（在本次 5 种子、12×12 设置下）。
- "干预通路已接通"：**已验证**（有提交和换臂记录）。
- "干预会损害性能"：**初步观察**，还需要更多种子和其他干预方式来确认。
- "程序自己决策更优"：**推测**，本实验没有直接测试这一点。

**下一步选择**

- 换假设：检查干预是否强制换臂，改为只提供提示，观察结果。
- 换判据：增加种子数量，确认结果不是偶然。
- 不建议直接结束这条路线，因为尚未测试其他干预方式。

## 八、Cline 任务的固定要求

在 Cline 任务中加入以下约定，每次任务结束必须输出：

1. 假设是什么
2. 实际结果是什么
3. 结论的证据等级
4. 下一步的选择（换假设 / 换判据 / 结束）

这样报告的读法统一，不依赖临场判断。
