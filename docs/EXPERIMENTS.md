# 实验方法（EXPERIMENTS）

本文档说明如何在 omega-cognitive-kernel 中做实验：怎么保证出错可以回退，怎么避免盲目前进，失败后怎么处理，以及怎么标注结论的可信程度。

---

## 一、基本原则

1. **可回退**：任何实验都能回到已知的稳定状态。
2. **先写期望，再动手**：没有假设和判据的实验不开始。
3. **失败有去向**：每次失败都必须选择一个明确的下一步。
4. **撤退是正式动作**：撤回改动也要有记录和理由。
5. **结论分级**：每个结论都标明证据强度，不混用。

---

## 二、回退机制

- **打标签**：实验开始前，在稳定点打 tag。
  ```bash
  git tag exp-YYYY-MM-DD-<简称>-baseline
  ```
- **独立分支**：实验在单独分支或 `git worktree` 中进行，不直接在 `main` 上修改。
- **存档未提交改动**：需要暂停时，把改动存起来，而不是丢弃。
  ```bash
  git stash push -m "<实验名>-存档"
  ```
- **失败分支保留**：失败的实验分支不删除，只在文档中标注结论。

---

## 三、实验卡（每个实验开始前填写）

```
实验名：
日期：
基线 tag：

假设：干预（或改动）会让哪个指标变好？理由是什么？

判据：
- 场景：
- 随机种子数量：
- 观察指标：
- 成功标准：
- 失败标准：

停止条件：
- 跑到多少次仍无结果则停止：
- 负收益超过多少则停止：
```

---

## 四、失败后的三种去向

每次失败，只能选择其中一个，不能只是加参数再跑：

1. **换假设**：说明原来的理由不成立，提出新的理由。
2. **换判据**：说明原来的衡量方式不合适，改用更合理的指标。
3. **结束这条路线**：写入文档，说明为什么放弃，留下什么教训。

---

## 五、撤回改动的记录方式

撤回改动和提交改动一样，需要留下记录，写在 `docs/EXPERIMENTS.md` 对应实验下：

- 尝试了什么
- 为什么撤回
- 留下了什么可复用的东西
- 下次如果再做，要避免什么

---

## 六、结论的证据等级

每个结论必须标注等级：

| 等级 | 含义 | 示例 |
|---|---|---|
| **已验证** | 有数据、有测试、有复现命令 | 5 个种子、12×12 基准，结果稳定复现 |
| **初步观察** | 只有少数几次结果，还不稳定 | 单个种子下看到的差异 |
| **推测** | 没有直接证据，只是合理猜测 | "可能是干预强制换臂导致的" |

**规则**：不能把"初步观察"写成"已验证"，也不能把"推测"当成结论引用。

---

## 七、示例：L2 干预实验（2026-11-21）

**实验卡摘要**

- 假设：负奖励触发 L2 干预，能影响下一次 bandit 选臂，从而改善长期表现。
- 场景：非平稳、降级、稳定三种环境。
- 种子：5 个，基准为 12×12。

**结果**

| 场景 | 换臂次数 | 奖励差（相对基线） | 最佳臂率差 |
|---|---|---|---|
| 非平稳 | 平均 1.0 次 | -0.0389 | -0.0806 |
| 降级 | 平均 1.0 次 | -0.0264 | -0.3056 |
| 稳定 | 未触发干预 | 持平 | 持平 |

**结论分级**

- "干预后奖励和最佳臂率下降"：**已验证**（在本次 5 种子、12×12 设置下）。
- "干预通路已接通"：**已验证**（有提交和换臂记录）。
- "干预会损害性能"：**初步观察**，还需要更多种子和其他干预方式来确认。
- "程序自己决策更优"：**推测**，本实验没有直接测试这一点。

**下一步选择**

- 换假设：检查干预是否强制换臂，改为只提供提示，观察结果。
- 换判据：增加种子数量，确认结果不是偶然。
- 不建议直接结束这条路线，因为尚未测试其他干预方式。

---

## 八、Cline 任务的固定要求

在 Cline 任务中加入以下约定，每次任务结束必须输出：

1. 假设是什么
2. 实际结果是什么
3. 结论的证据等级
4. 下一步的选择（换假设 / 换判据 / 结束）

这样报告的读法统一，不依赖临场判断。
